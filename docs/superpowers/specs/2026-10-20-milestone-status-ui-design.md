# 마일스톤 현황(/my-project/milestones) UI 개편 설계

- 날짜: 2026-10-20
- 목업: https://claude.ai/artifact/HsLm3HVFKyfK7RzBMp2mNF (현재/제안 데스크톱/상태 해부/모바일 4개 보드)
- 결정자 확인: 완료 확인 모달 제거, 지연 건은 별도 섹션 없이 필터로만 모음

## 1. 의도

챔피언이 자기 마일스톤을 체크인하는 화면에서 (1) "진행 시작"을 눌렀을 때 상태 변화가 눈에 들어오지 않고, (2) 상태 표시(우상단 텍스트)와 액션 버튼(좌하단)이 떨어져 있으며, (3) 카드가 ~130px라 8건만 돼도 두 화면을 넘긴다. 데이터 모델과 API는 그대로 두고 화면 구조만 바꿔 세 문제를 한 번에 없앤다.

## 2. 목표 / 비목표

**목표**
- 상태와 다음 액션을 한자리(상태 스테퍼)에 둔다. 단계 전환은 같은 자리에서 색이 채워지는 방식으로 보인다.
- 행 높이를 46px(데스크톱) 수준으로 줄이고, 노트·작업 로그·관리자 답변·기한 변경은 펼쳤을 때만 보인다.
- "단계"(미시작→진행중→완료)와 "일정"(D-배지, 지연)을 분리해 표현한다. 지연 건은 자기 그룹 안에 남고, 필터 칩으로 모아 본다.
- 완료 확인 모달을 없애고 토스트의 "되돌리기"로 대체한다.

**비목표**
- `milestones` 스키마, `computeStatus`, PATCH 라우트 변경. (단계 전환은 기존 `is_manual_progress` / `is_manual_completed` PATCH를 그대로 사용)
- 관리자 화면(간트·칸반)과 과제정의서 페이지의 마일스톤 편집 드로어.
- 주차(week_number) 기반 그룹핑 복원. 모바일도 데스크톱과 같이 상위 마일스톤 기준으로 묶는다.

**안티골**
- 지연 건이 다른 섹션으로 "튀어나가" 단계 맥락을 잃는 것. (현재 구조의 문제를 그대로 재현하면 실패)
- 완료 처리가 되돌릴 수 없게 되는 것.

## 3. 화면 구조 (데스크톱, md 이상)

```
[차터 선택(2개 이상일 때)]
[요약 카드]  완료 n / 전체 N · pct%  | 색 분할 진행률 바 | 범례(완료·진행중·지연·미시작)
            오른쪽: 이번 주 마감 n건 · 지연 n건 · 이슈 검토중 n건 · 오늘 날짜
[필터 칩]    전체 N · 진행중 n · 지연 n · 예정 n · 완료 n
[그룹]       ▾ 상위 마일스톤 제목 · 기간 · 미니 진행률(자식 완료 수/자식 수) ····· [상위 마일스톤 자체 스테퍼]
  [행]       | 레일 | 제목 [노트][로그 n] | 기간 D-배지 | (이슈 보고 | 이슈 검토중) [시작|진행중|완료] | ▾ |
  [펼침]     진행 노트(편집) · 관리자 답변 · 노트 편집/기한 변경/이슈 보고 링크 | 작업 로그 목록
```

- **그룹**: `parent_milestone_id`가 null이고 자식이 1개 이상인 마일스톤이 그룹 헤더가 된다. 헤더 오른쪽 끝에 그 상위 마일스톤 자신의 스테퍼를 둬 현재처럼 상위 마일스톤도 직접 완료 처리할 수 있게 한다(자식 완료가 상위를 자동 완료하지 않는 기존 동작 유지). 자식이 없는 최상위 마일스톤은 헤더 없는 암시적 그룹(목록 맨 위)에 행으로 표시한다.
- **행 그리드**: `4px | 1fr | 168px | 256px | 32px`, 열 간격 12px, 최소 높이 46px, 하단 1px 구분선. 호버 시 배경 `#fafafb`.
- **레일 색**: 완료 초록 / 지연 빨강 / 진행중 파랑(`--accent`) / 미시작 회색.
- **제목 옆 칩**: `note`가 있으면 "노트", 작업 로그가 있으면 "로그 n" (로그 수는 펼쳐서 불러온 뒤에만 표시, 초기에는 "노트" 칩만).
- **D-배지** (마감일 기준, 오늘 = 서버가 KST로 한 번 계산해 내려준 `todayStr`(`kstTodayStr`). 클라이언트에서 `new Date()`를 쓰지 않아 hydration 불일치가 없다):
  - 완료: `완료` (회색)
  - 마감일 없음: 배지 없음, 행에 "기한 설정" 링크
  - 일정 지연(§4): `D+n 지연` 빨강 채움. 마감 전인데 시작일이 지났고 미시작이면 `시작 지연`, 그 밖의 마감 전 일정 지연(예: 이슈 검토중)은 `지연` 빨강 채움
  - 오늘 마감: `D-DAY` 주황, 7일 이내: `D-n` 주황, 그 외: `D-n` 회색
- **액션 클러스터**: 지연이고 이슈 미보고면 "이슈 보고" 빨강 아웃라인 버튼, 이슈 보고 후 검토 전이면 "이슈 검토중" 배지. 그 오른쪽에 스테퍼.
- **펼침 패널**: 2열. 왼쪽 진행 노트(진행중일 때만 편집 가능, 기존 규칙)·관리자 답변·링크(노트 편집, 기한 변경/연장/설정, 이슈 보고). 오른쪽 작업 로그(기존 `MilestoneActivityLogToggle`을 펼침 시 자동 전개). 노트 편집 상태는 행(카드)이 `useNoteEditor` 훅으로 소유하므로 접었다 펼쳐도 초안이 남고, 접힌 동안에는 제목 옆(모바일은 기간 줄)에 `노트 편집중` 칩을 보인다. 편집기와 칩은 단계가 진행중일 때만 그린다(완료·되돌리기로 단계가 바뀌면 숨기고, 다시 진행중이 되면 초안이 되살아난다). 데스크톱·모바일 레이아웃은 각각 초안을 가지므로 브레이크포인트를 넘나들면 초안이 공유되지 않는다(허용).
- **빈 상태**: 필터에 해당 없음 → 그룹 안에 "이 필터에 해당하는 마일스톤이 없습니다." 전체 0건 → 기존 문구 유지.

## 4. 상태 스테퍼 (`StageStepper`)

세 칸 `[시작] [진행중] [완료]`, 높이 30px(데스크톱) / 34px(모바일), 너비 216px(데스크톱) / 전폭(모바일).

| 단계 | 1칸 | 2칸 | 3칸 |
|---|---|---|---|
| 미시작 | `▶ 시작` 파랑 글자, 클릭 가능 | `진행중` 흐림 | `완료` 흐림 |
| 진행중 | `✓ 시작` 흐림 | `진행중` 파랑 채움 | `완료로` 초록 글자, 클릭 가능 |
| 완료 | `✓ 시작` 흐림 | `✓ 진행중` 흐림 | `✓ 완료` 초록 채움 |

- **단계 도출**(`deriveStage`): 서버 `computeStatus` 순서대로 플래그 우선 — `is_manual_completed` → 완료, `is_manual_progress` → 진행중, 그 외 `status === 'completed'` → 완료, `status === 'in_progress'` → 진행중, 나머지(`delayed` 포함) 미시작. 즉 지연은 단계가 아니다(서버는 `due_date`가 있을 때만 `status`를 다시 계산하므로 플래그를 먼저 본다).
- **일정 지연**(`isScheduleDelayed`): 완료가 아니면서 `status === 'delayed'` 이거나 `due_date < 오늘` 이거나 (`start_date < 오늘` 이고 단계가 미시작). 사이드바 배지와 같은 규칙.
- 과제정의서 미승인(`charterApproved === false`)이면 스테퍼 전체 비활성 + `title="과제정의서 승인 후 진행할 수 있습니다"`. 지금의 "과제 정의서 검토중" 회색 칩을 대체한다.
- 클릭 가능한 칸만 `<button>`이 활성이고 나머지는 `disabled`. 그룹 `role="group" aria-label="진행 단계"`.
- 접근성: 비활성 사유는 그룹 `title`과 함께 각 버튼의 `aria-describedby`(sr-only 텍스트)로도 노출한다. 현재 단계 칸은 `aria-current="step"`. `▶/✓` 글리프는 `aria-hidden`이라 접근성 이름은 `시작`/`진행중`/`완료`/`완료로`. 그룹은 `overflow:hidden`을 쓰지 않고(포커스 링 보존) 양 끝 칸에 라운드를 준다. 흰 글자는 `--text-inverse`. 모바일 펼침 버튼은 44×44px.

## 5. 상태 전환과 되돌리기

| 클릭 | PATCH body | 토스트 |
|---|---|---|
| 시작 | `{ is_manual_progress: true, is_manual_completed: false, bottleneck_type: null, bottleneck_note: null }` (기존과 동일). 단, 이슈 검토중(`isIssuePending`)이면 `{ is_manual_progress: true, is_manual_completed: false }`만 보내 보고를 철회하지 않는다 | "진행중으로 표시했습니다." + 되돌리기 |
| 완료로 | `{ is_manual_completed: true, bottleneck_type: null, bottleneck_note: null }` (기존과 동일) | "완료로 표시했습니다." + 되돌리기 |
| 되돌리기(시작 후) | `{ is_manual_progress: false }` | "되돌렸습니다." |
| 되돌리기(완료 후) | `{ is_manual_completed: false, is_manual_progress: <완료 전 단계가 진행중이었으면 true, 아니면 false> }` | "되돌렸습니다." |

- 이슈 보고 PATCH는 `{ bottleneck_type, bottleneck_note, is_manual_completed: false }`이며 `is_manual_progress`를 건드리지 않는다(진행중 항목은 진행중 단계를 유지한 채 일정 지연으로 표시).
- 확인 모달 없음. PATCH는 즉시 보내고, 토스트는 6초간 "되돌리기" 액션을 보인다(sonner `toast.success(msg, { action, duration: 6000 })`).
- 알려진 한계(결정): 완료 PATCH는 즉시 관리자 Slack/메일 알림을 보낸다. 되돌려도 알림은 취소되지 않는다. 지연 커밋 방식은 페이지 이탈 시 유실 위험이 있어 채택하지 않는다.
- 403 `charter_not_approved`는 "과제정의서 승인 후 진행할 수 있습니다." 토스트로 안내.
- 되돌리기는 같은 마일스톤의 **가장 최근 전환**에만 유효하다. 마일스톤별 전환 순번을 두고, 새 전환(시작·완료·되돌리기)이 성공하면 이전 토스트를 닫는다. 그래도 눌리면 `"이미 다른 변경이 있어 되돌릴 수 없습니다."`, 같은 항목이 처리 중이면 `"처리 중입니다. 잠시 후 다시 시도해주세요."`(둘 다 info 토스트, PATCH 없음). 이슈 보고·노트·기한 변경은 단계를 바꾸지 않으므로 순번을 올리지 않는다.

## 6. 필터

| 칩 | 조건 |
|---|---|
| 전체 | 게시(published)된 전체 |
| 진행중 | 단계 진행중 이고 일정 지연 아님 |
| 지연 | 일정 지연(이슈 검토중 포함) |
| 예정 | 단계 미시작 이고 일정 지연 아님 |
| 완료 | 단계 완료 |

요약 카드의 네 숫자도 같은 분류를 쓴다(합이 전체와 같아야 한다). 필터는 클라이언트 상태이며 URL에 넣지 않는다. 상위 마일스톤(그룹 헤더)은 필터 대상이 아니고 자식이 0건이면 "해당 없음" 문구를 보인다.

## 7. 모바일 (md 미만)

같은 그룹·같은 분류. 카드는 `레일 | (제목 ··· 펼침 버튼) / (기간 D-배지 [이슈 검토중]) / ([이슈 보고] 스테퍼 전폭)` 3단, 흰 배경 카드에 10px 라운드, 페이지 배경 `--surface-minimal`. 펼침 패널은 데스크톱과 같되 1열.

## 8. 바뀌는 파일 (빌더용 요약)

- 신규 `lib/milestone-view.ts`: 순수 함수(단계·지연·D-배지·필터·요약·그룹핑).
- 신규 `components/milestones/StageStepper.tsx`, `MilestoneRow.tsx`, `MilestoneSummary.tsx`, `IssueReportDialog.tsx`(기존 CheckinTab의 이슈 모달 이관).
- 수정 `app/(champion)/my-project/milestones/MilestonesClient.tsx`(섹션 구조 제거, 그룹·필터·되돌리기), `components/MobileMilestoneCard.tsx`, `components/milestones/MilestoneActivityLogToggle.tsx`(`defaultExpanded` prop).
- 삭제 `components/CheckinTab.tsx`(MilestonesClient 외 사용처 없음).

## 9. 빌더에게 맡기는 것

- 토큰 색상값은 `app/globals.css`의 변수(`--accent`, `--error`, `--success`, `--amber`, `--surface-minimal`, `--border`)를 쓴다. 목업의 hex는 참고용.
- 작업 로그 수를 행 칩에 보이는 방식(펼친 뒤 캐시)은 `MilestoneActivityLogToggle`의 `onLoaded?(count)` 콜백 정도로 가볍게 처리.
- 그룹 접기 상태는 세션 내 React 상태로만 유지.
